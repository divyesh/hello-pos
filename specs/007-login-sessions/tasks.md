# Tasks: Login and Sessions

**Input**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md),
[data-model.md](data-model.md), [contracts/openapi-additions.yaml](contracts/openapi-additions.yaml),
[quickstart.md](quickstart.md)

**Tests**: Required (Constitution III, VI, VIII). Each story's tests come first and must fail first.
API tests run against real PostgreSQL as the app login; Android tests are JVM unit tests (JUnit 6,
Turbine, MockWebServer).

## Conventions

- .NET through `scripts/dotnet.ps1`; Android with `JAVA_HOME` = Android Studio's JBR.
- Contract first; regenerate the web Kiota client (Android regenerates on build).
- Never return, log or audit a PIN, token, code or credential except in the one response that issues it.
- The business always comes from an authenticated secret (device credential, session token) or a
  pairing code via `pos.pairing_business`, never from request data.

## Phase 3: User Story 1 - Register a POS device (P1) 🎯 MVP
